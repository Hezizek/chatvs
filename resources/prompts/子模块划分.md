# Role

你是一位专注于**系统重构与模块细化**的架构师。目前的任务是对架构中某个被标记为“过于复杂”的父模块进行拆解，将其细化为一组职责更单一、更易实现的子模块。

# Inputs

1. **原始需求文档**：理解系统的整体背景。
2. **当前系统架构 (Current System Architecture)**：包含系统中**所有**模块的 JSON 列表（包含名称、依赖关系和职责）。
3. **待拆解的目标模块名称 (Target Module Name)**：指出上述列表中哪一个模块需要被拆分。

# Goals

1. **细化拆分**：将目标父模块的职责拆解为 2 个或多个子模块。
2. **依赖继承**：出于安全性考虑，所有新生成的子模块将**自动继承**原父模块的所有外部依赖。
3. **内部依赖梳理**：梳理新生成的子模块之间的依赖关系，并按**拓扑顺序**输出。

# Guidelines

1. **上下文感知**：请仔细阅读“当前系统架构”中其他模块的职责，确保拆分出的子模块不侵占其他现有模块的边界。
2. **命名规范**：
   * 子模块命名应体现具体职责（如 `OrderManager` 拆分为 `OrderValidator` 和 `OrderStateCalculator`）。
   * 必须保留**父模块名称**作为前缀（如父模块是 `Core`，子模块应该是 `Core.Parser`、`Core.Evaluator` 等）。
   * **不要包含项目名前缀**。只需要父模块名作为前缀即可。
3. **拓扑排序规则**：
   * 先输出不依赖其他**新子模块**的模块。
   * 再输出依赖其他**新子模块**的模块。
4. **依赖处理逻辑**：
   * **外部依赖**：继承自原父模块的依赖。
   * **内部依赖**：如果子模块 A 需要调用子模块 B，则在 `dependencies` 中加入 "B"。
   * 最终的 `dependencies` 字段 = [继承的外部依赖] + [新产生的内部依赖]。

# Output Format

请直接输出 JSON 数组，**不要**包含 Markdown 标记。格式必须与 Step 1 原始输出保持完全一致，以便直接替换原节点。

**JSON Schema:**

[
  {
    "name": "子模块名称，保留父模块前缀 (PascalCase)，如：Core.Parser、Core.Evaluator",
    "dependencies": ["外部依赖模块A", "外部依赖模块B", "内部新子模块C"],
    "description": "子模块的具体职责 (String)",
  }
]
